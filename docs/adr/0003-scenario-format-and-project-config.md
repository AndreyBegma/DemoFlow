# ADR-0003: Scenario format, locators, secrets and project config

Status: accepted · Date: 2026-10-17

## Context

Scenarios are written by people and generated by AI agents; they must be
validated before execution, versioned with the project, and safe to run on a
command from the website (vision §4, §11).

## Decision

1. **Scenarios are JSON validated by a zod 4 schema** in `@demoflow/core`. The
   same schema produces the TypeScript types and a JSON Schema, which is
   published for editors and used as the MCP tool input schema.
2. **Scenarios live in the project as `demoflow/**/*.demo.json`.** They are
   committed and reviewed like code. A scenario's id is its path relative to
   the project root.
3. **Locators are structured objects**, mapped one-to-one onto Playwright:
   `{ role, name?, exact? }`, `{ label }`, `{ testId }`, `{ text, exact? }`,
   `{ placeholder }`. A CSS selector is accepted only as an explicit
   `{ css }` and produces a validation warning. Coordinates are never a
   locator.
4. **Actions** (the full set of vision §4): `navigate`, `waitFor`, `click`,
   `fill`, `select`, `hover`, `scroll`, `assertVisible`, `assertText`,
   `screenshot`, `marker` (a scene or caption), `wait` (milliseconds, capped).
5. **Secrets never appear in a scenario.** `fill` takes either `value` or
   `valueFrom: { env: "NAME" }`. A value from the environment is written to the
   timeline as `***`, and the renderer covers the field's box for as long as it
   is visible. The raw source recording is local and is **not** masked; the
   documentation says so.
6. **Project configuration is `demoflow.config.json`** at the project root:
   data, validated by zod, never code. It holds `baseUrl`, the allowed origins,
   an optional `devCommand` with `readyUrl` (ADR-0008), the artifact directory
   and render defaults. The runner never executes JavaScript from the project.

## Consequences

- Agents get a precise schema to generate against and precise errors
  (`steps[3].target: expected one of role|label|testId|text|placeholder|css`).
- Pages without accessible names or test IDs need a `{ css }` locator, with a
  warning, or a change to the page.
