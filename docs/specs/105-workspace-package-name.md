# `npx demoflow` inside the monorepo resolves to the workspace package

Issue: [#105](https://github.com/AndreyBegma/DemoFlow/issues/105) · bug ·
Decisions: spec [75](75-npm-release.md) (the staged npm package)

## Summary

Inside this repository `npx demoflow@0.1.0 …` fails with
`sh: demoflow: command not found`: npx finds the private workspace package
`apps/cli`, whose `package.json` is named `demoflow` [Confirmed:
`apps/cli/package.json`], instead of the published one. Outside the repository
the published package works. The fix renames the workspace package and keeps
`demoflow` only as the name of the staged package in `apps/cli/dist/npm`.

## Scope

### In scope

- `apps/cli/package.json`: `name` becomes `@demoflow/cli` (still `private:
  true`); the `bin` entry stays `demoflow`.
- `apps/cli/scripts/manifest.ts` (`publishManifest`): the generated manifest's
  `name` is the constant `demoflow`, not the workspace name; a test pins it.
- Every `--filter=demoflow` becomes `--filter=@demoflow/cli`:
  `.github/workflows/execution-plane.yml`, `.github/workflows/package-smoke.yml`,
  `.woodpecker/release.yml` [Confirmed: `git grep`].
- `scripts/release/*` and `deploy/README.md`: any reference to the workspace
  name is updated; the published name stays `demoflow`.
- `bun.lock` regenerated by `bun install`.

### Out of scope

- The program name shown by `--help` and `--version`, the data directory name,
  and the MCP server name — they stay `demoflow`.
- Publishing a new version (the next release carries it).

## Decisions

1. **`@demoflow/cli`**, matching the other workspace packages. — orchestrator.
2. **The published name is a constant in `manifest.ts`**, so renaming the
   workspace can never rename the npm package. — orchestrator.

## Acceptance criteria

- [ ] From the repository root and from `apps/fixture`, after `bun install`,
      `npx demoflow@0.1.0 --version` prints `0.1.0` (manual check, output in
      the PR body).
- [ ] `bun run build` stages `apps/cli/dist/npm/package.json` with
      `"name": "demoflow"` and the `demoflow` bin (manifest test).
- [ ] `package-smoke` (three OSes) and `execution-plane` stay green; the
      release workflow's build step uses the new filter (Woodpecker green on
      the PR).
- [ ] `bun run check` passes.
