# Scenarios

A scenario is a JSON file, `demoflow/**/*.demo.json`, that lists the steps a
browser runs against your app. `demoflow validate <file>` checks it against the
schema and reports problems by path, such as `steps[1].target`.

```json
{
  "schemaVersion": 1,
  "name": "Sign in",
  "description": "A returning user signs in.",
  "baseUrl": "http://localhost:3000",
  "viewport": { "width": 1920, "height": 1080 },
  "steps": []
}
```

| Field | Meaning |
|---|---|
| `schemaVersion` | Always `1`. |
| `name` | Required. Shown on the intro card. |
| `description` | Optional. Shown under the name on the intro card. |
| `baseUrl` | Optional. Overrides the project config for this scenario. |
| `device` | `"desktop"` (default) or `"phone"`. See [Record as a phone](#record-as-a-phone). |
| `viewport` | The browser size. Default 1920×1080, or 412×914 for a phone. |
| `data` | Lists a `repeat` step runs over. See [Repeat over data](#repeat-over-data). |
| `setup` | Optional. 1 to 200 steps that run before the recording starts. See [Off-camera steps](#off-camera-steps). |
| `steps` | 1 to 200 steps. |

## Record as a phone

`"device": "phone"` records the scenario as a phone instead of a desktop:

```json
{
  "schemaVersion": 1,
  "name": "Sign in on a phone",
  "device": "phone",
  "steps": [{ "action": "click", "target": { "role": "button", "name": "Sign in" } }]
}
```

- The viewport is 412×914 unless the scenario sets `viewport`.
- The browser is a touch device with a mobile user agent, and the page gets its
  mobile `<meta name="viewport">`.
- The steps are the same; `click` taps.
- The video shows each tap as the click ring and draws no cursor arrow.
- The vertical and square crops follow targets up and down the page.

The page is recorded at its CSS size, so a 412-wide page is upscaled about 2.6×
to fill a 1080-wide vertical or square frame. Those crops look softer than a
desktop one; this is expected, not a bug. The landscape video stays sharp.

## Locators

A step that acts on an element names it with a `target`, which holds exactly
one of these. They map one-to-one onto Playwright's locators, and there are no
coordinates.

| Key | Finds |
|---|---|
| `role` (with optional `name`) | an element by ARIA role and accessible name |
| `label` | a form field by its label |
| `testId` | an element by its test id |
| `text` | an element by its text |
| `placeholder` | a field by its placeholder |
| `css` | a CSS selector; accepted with a warning, prefer the others |

`role`, `label`, `text` and `placeholder` take `"exact": true` to match the
whole string instead of a part of it.

## Steps

Every step has an `action`. Every step may also carry a `caption`, a
`timeoutMs`, a [`hold`](#hold) and `"record": false` (see
[Off-camera steps](#off-camera-steps)).

| Action | What it does | Fields |
|---|---|---|
| `navigate` | Opens a page. | exactly one of `path` (starts with a single `/`) or `url` |
| `waitFor` | Waits for an element. | `target`, `state` (`visible` by default, or `hidden`) |
| `click` | Clicks an element. | `target` |
| `fill` | Types into a field. | `target`, exactly one of `value` or `valueFrom`; optional `typingDelayMs` |
| `select` | Picks an option of a select. | `target`, `option` |
| `hover` | Moves the pointer over an element. | `target` |
| `press` | Presses a key or a chord, such as `Enter` or `Control+a`. | `key`, optional `target` |
| `scroll` | Scrolls the page or a container. | exactly one of `to` (`top` or `bottom`) or `target`; optional `within` |
| `assertVisible` | Fails the run unless the element is visible. | `target` |
| `assertText` | Fails the run unless the element has the text. | `target`, `text`, `match` (`contains` by default, or `exact`) |
| `screenshot` | Saves a still. | `name` (lowercase letters, digits and `-`) |
| `waitForReady` | Waits until your app signals it is ready. See [Application SDK](/docs/sdk#tell-a-scenario-you-are-ready). | `name` |
| `marker` | Marks a scene or a caption in the video. | `title`, `kind` (`scene` by default, or `caption`) |
| `wait` | Pauses on screen. | `ms` (1 to 5000) |
| `repeat` | Runs steps once per item of a list. | See [Repeat over data](#repeat-over-data). |
| `include` | Runs the steps of a fragment. | `fragment`, optional `with`. See [Fragments](#fragments). |

### caption

`caption` is up to 120 characters of text shown in the video while the step
runs.

```json
{
  "action": "click",
  "target": { "role": "button", "name": "Publish" },
  "caption": "Publish the post"
}
```

### timeoutMs

`timeoutMs` is how long the step may wait for its element or condition before
the run fails: 100 to 60000 ms, 10000 by default.

### Zoom

`zoom` moves the camera in on the step's target. `true` uses the renderer's
default strength; a number from `1` (no zoom) to `3` sets it. It is available on
steps that have a target, `waitFor` for a hidden element excepted, and on
`press` only when the `press` has a `target`. Nothing zooms unless a step asks.

```json
{
  "action": "click",
  "target": { "role": "button", "name": "Publish" },
  "zoom": 1.8
}
```

### Pacing

A recording plays slowly enough to follow. After each visible step
(`navigate`, `click`, `hover`, `fill`, `select`, `press`, `scroll`,
`assertVisible`, `assertText`) the video stays on the result for a moment
before the next step, and a `fill` types one character at a time.

The top-level `pacing` object sets this for the whole scenario. Every field is
optional and has a default:

| Field | Default | Range | What it does |
|---|---|---|---|
| `stepDwellMs` | 1000 | 0 to 10000 | Pause after each visible step. `0` turns it off. |
| `typingDelayMs` | 80 | 0 to 500 | Pause between two typed characters of a `fill`. |

A step overrides the scenario's pacing for itself: [`hold`](#hold) (0 to 10000)
on any step replaces the dwell, and `typingDelayMs` (0 to 500) on a `fill`. A
`hold` also adds a pause after a step that has none by default, such as a
`marker`. The last step does not dwell unless it sets `hold`; the end hold
follows it. The end hold is [`render.endHoldMs`](/docs/config#render), 3500 ms
by default.

```json
{
  "pacing": { "stepDwellMs": 700, "typingDelayMs": 60 },
  "steps": [
    { "action": "fill", "target": { "label": "Title" }, "value": "Hello", "typingDelayMs": 120 },
    { "action": "click", "target": { "role": "button", "name": "Publish" }, "hold": 2000 },
    { "action": "assertVisible", "target": { "text": "Hello" } }
  ]
}
```

A `wait` still pauses on top of the dwell. Pacing never slows down
[setup and off-camera steps](#off-camera-steps), and a check run
(`demoflow run --check`) neither dwells nor holds the end.

### hold

`hold` keeps the page on screen after the step, for 0 to 10000 ms. The run
waits that long once the step is done, and the video plays the whole hold at
real speed: the [idle trim](/docs/config#render) never shortens it. `0` turns the dwell off. A step that
fails does not hold. `hold` is refused on an off-camera step
(`"record": false`).

Use `hold`, not `wait`, to show something. A `wait` on a still page is idle
time, and the render shortens it to `render.idle.compressToMs` (400 ms by
default).

#### Show the result

Assert the result, zoom in on it and hold it. An assertion with `zoom` keeps the
camera on the element it found through its hold, and outlines it:

```json
{
  "action": "assertVisible",
  "target": { "text": "My first post" },
  "zoom": true,
  "hold": 2000
}
```

The outline is drawn where the element was when the assertion passed, so hold
an element that has stopped moving.

Every successful video also ends on its last frame for
[`render.endHoldMs`](/docs/config#render) (3500 ms by default), after the last
step's own `hold`.

### Scene markers

A `marker` with `kind: "scene"` starts a new scene. It gets a scene card in the
video unless [cards](/docs/config#cards) are off. Your app can start scenes
and show captions itself; see [Application SDK](/docs/sdk#scenes-and-captions-from-your-app).

## Secrets and masking

A secret never appears in a scenario. A `fill` takes its text from an
environment variable instead of `value`:

```json
{
  "action": "fill",
  "target": { "label": "Password" },
  "valueFrom": { "env": "DEMO_PASSWORD" }
}
```

- The value is read from the environment when the run starts. It does not touch
  disk or logs, and the timeline records a placeholder instead of it.
- A field filled this way is masked: the video blurs it from the `fill` until
  the field leaves the page.
- To blur something that is not a filled field, such as an API key your app
  shows, mark it in the page with [`data-demoflow-mask`](/docs/sdk#mask-an-element).
- `valueFrom` takes a variable name (`A-Z`, `0-9` and `_`) and never a `{{…}}`
  placeholder, so data lists cannot carry secrets either.
- If the variable is missing, the run fails at readiness, before the browser
  starts, with exit code `2`.

## Repeat over data

A scenario can declare `data` lists and run a group of steps once per item.
`{{post.text}}` is the item's `text` field and `{{index}}` its 1-based position.
They work in every string of a step inside the `repeat`.

```json
{
  "schemaVersion": 1,
  "name": "Post three updates",
  "data": {
    "posts": [
      { "text": "Hello" },
      { "text": "Shipping today" },
      { "text": "Thanks!" }
    ]
  },
  "steps": [
    { "action": "navigate", "path": "/feed" },
    {
      "action": "repeat",
      "each": "posts",
      "as": "post",
      "caption": "Three posts",
      "steps": [
        { "action": "click", "target": { "role": "button", "name": "Compose" } },
        { "action": "fill", "target": { "label": "Post" }, "value": "{{post.text}}" },
        { "action": "click", "target": { "role": "button", "name": "Publish" } }
      ]
    }
  ]
}
```

- A list holds 1 to 100 items. An item is an object of strings, numbers and booleans.
- `each` names the list; `as` names the item and defaults to `item`. `index` is taken by `{{index}}`.
- A `repeat` holds 1 to 50 steps and no `repeat` of its own: loops are one level deep.
- Its `caption` is shown once, before the first iteration.
- Every field a step uses must be in every item, and a URL, path or key must be valid once filled in. `demoflow validate` reports a problem by step path, such as `steps[1].steps[1].value`, before anything runs.
- `{{…}}` is an error outside a `repeat`, except `{{params.…}}` in a [fragment](#fragments). Write `\\{{` in JSON for a literal `{{`.
- The timeline and `result.json` count the expanded steps. A failure reads like `step 4 (repeat steps[1], iteration 3)`.

## Fragments

A fragment is a list of steps that several scenarios share, such as signing
in. It lives in `demoflow/fragments/<name>.json`, or under the `fragmentsDir`
the [project config](/docs/config) names, and a scenario runs it with an
`include` step:

```json
{
  "schemaVersion": 1,
  "description": "Signs the demo user in.",
  "params": {
    "next": { "description": "Where to go once signed in.", "default": "/" }
  },
  "steps": [
    { "action": "navigate", "path": "/login" },
    { "action": "fill", "target": { "label": "Email" }, "valueFrom": { "env": "DEMO_LOGIN_EMAIL" } },
    { "action": "fill", "target": { "label": "Password" }, "valueFrom": { "env": "DEMO_LOGIN_PASSWORD" } },
    { "action": "click", "target": { "role": "button", "name": "Sign in" } },
    { "action": "navigate", "path": "{{params.next}}" }
  ]
}
```

```json
{
  "action": "include",
  "fragment": "sign-in",
  "with": { "next": "/projects/demo-project" }
}
```

- The name is the file's path under the fragments directory, without `.json`:
  `sign-in`, or `auth/sign-in` for `auth/sign-in.json`. A fragment file must be
  inside the project.
- `params` declares what `with` may pass. A parameter without a `default` is
  required. Values are strings, numbers or booleans, and steps use them as
  `{{params.<name>}}`.
- A fragment can include other fragments, up to 8 deep. It cannot hold a
  `repeat`, and an `include` cannot sit inside a `repeat`.
- `valueFrom.env` works in a fragment as in a scenario, so secrets stay out of
  both.
- The steps are inlined when the scenario is loaded: the timeline, `result.json`
  and the run's `scenario.json` show them as ordinary steps.
- `demoflow validate` checks every fragment a scenario includes. A missing
  fragment, an include cycle or a bad parameter is reported at the `include`,
  with the fragment file and step, such as
  `steps[0].fragment: unknown fragment sign-in: no demoflow/fragments/sign-in.json`
  or `steps[0]: in demoflow/fragments/sign-in.json steps[4].path: …`.

The JSON schema for fragment files is `fragment.schema.json` in
`@demoflow/core`.

## Off-camera steps

Steps the video should not show, such as signing in, run off camera. Put them
in the scenario's `setup`, or give the opening steps (or an `include`)
`"record": false`:

```json
{
  "schemaVersion": 1,
  "name": "Create a project",
  "setup": [
    { "action": "include", "fragment": "sign-in", "with": { "next": "/projects" } }
  ],
  "steps": [
    { "action": "click", "target": { "role": "button", "name": "New project" } }
  ]
}
```

- Off-camera steps run first, in a browser context that records nothing. Its
  cookies and local storage carry over to the recorded context, which opens on
  the page the off-camera steps ended on. The video starts there, already
  signed in, on the first recorded step.
- Only the opening steps can be off camera: `setup`, then any leading steps
  with `"record": false`. A `"record": false` step after a recorded one is an
  error, and at least one step must be recorded.
- `record` goes on a `repeat`, not on the steps inside it. Steps in `setup` are
  off camera already and take no `record`.
- The page is loaded again when recording starts, so state held only in memory
  or in session storage does not carry over.
- The timeline holds only the recorded steps, and its times and markers match
  the video. Step numbers in `result.json` and errors still count the
  off-camera steps, `setup` first.
- A failed off-camera step fails the run before anything is recorded.

`demoflow record` and [`@demoflow/playwright`](/docs/playwright) write plain
steps; add `include` and `setup` to their scenarios by hand afterwards.
